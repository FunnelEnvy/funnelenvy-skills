# Changelog

## [Unreleased]

### Added
- Dual-mode I/O (KB mode): reads the scope's silver CRO artifacts from a bound knowledge base instead of .claude/context/ and writes a typed gold-experiment-roadmap artifact; --scope and --no-kb flags; mode resolution with loud legacy fallback; gold frontmatter contract with gold-to-silver depends_on; supersede-in-place re-runs; post-write validation gate; Profile Schema Equivalence rule in detect.md Step 1c (content-equivalence trigger evaluation for performance profiles lacking schema_version); legacy .claude/context/ behavior unchanged (chg_2026-06-03_hypothesis-generator-kb-native)
- Archetype architecture layer (resolver + loader): Phase 1 resolves an archetype from category.primary via a case-insensitive substring mapping (procurement, b2b-saas, b2c-ecommerce, or base-only on no match) and loads the matched archetype pattern module additively on top of the base library (modules/experiment-patterns.md). detect.md Step 2 gains an archetype-precedence matching rule (archetype patterns checked first, base patterns still fire on an uncovered page + mechanism, ties resolve to the archetype baseline via the existing Phase 3 Step 8 dedup). The pre-flight summary reports the resolved archetype and loaded modules, and Module Dependencies lists patterns-procurement.md and patterns-b2b-saas.md as scope-loaded. Additive and inert until an archetype module exists (H3 ships procurement): every scope currently loads the base library only, so behavior is unchanged, and a missing archetype module is skipped silently with no hard failure.
- Procurement archetype pattern module (modules/patterns-procurement.md): six schema-complete patterns (PR-01 Authenticated Gate Value Recovery, PR-02 Gate Route Disambiguation, PR-03 Procurement Model Explanation Layer, PR-04 Decision Data at the Commit Surface, PR-05 Commit-Surface Default-State Prompt, PR-06 Rep-Channel Self-Service Bridge), loaded additively by the archetype resolver when category.primary resolves to procurement. Measurement-maturity reframe across score.md, ice-scoring.md, and construct.md: the condition 'performance data present but conversions lack page attribution' caps revenue-attribution confidence only (no blanket Confidence cap), defaults the target metric to a variant-instrumented proxy, and emits a scored measurement-enablement prerequisite-experiment; Confidence is earned on proxy interpretability; construct.md Step 5b estimates feasibility on the proxy base rate instead of returning 'Cannot estimate' when a proxy is instrumentable. Context-derived hypotheses may exceed Confidence 3 only when they both cite named corroborating evidence and target a high-traffic, proxy-readable surface. Validator section [11] checks the procurement module exists with 6 patterns, and section [6] prohibited-content greps extended to cover it.
- Engagement-context reasoning input (engagement-constraints, optional): a soft input capturing delivery and governance state (release calendar, approval/governance bandwidth, measurement-infrastructure timeline, internal-tester/QA constraints, delivery-match risk). New detect.md Step 1d 'Engagement-Constraint Reasoning' is a reasoning procedure (five derivation patterns plus a generalization rule and two worked examples) that derives per-experiment timing, concurrency, tier, feasibility, and launch-gate implications from the input; it produces constraints, never hypotheses. score.md Step 7 gains a top-priority Layer 0 applying the derived constraints (release-window timing overrides ordering, concurrency ceiling, tier ceiling on high-risk surfaces) and renders the reasoning in the Sequencing Rationale prose. When the input is absent, Step 1d is skipped and sequencing falls back to LIFT plus dependencies, unchanged. The skill owns the reasoning; the facts come from the input. Legacy: optional .claude/context/engagement-constraints.md; KB mode: maps to an engagement-context artifact. Also fixed a stale 'three layers' miscount in score.md Step 7.
- Output Format quality blocks and falsifiable magnitude: every hypothesis renders an 'Expected effect and read threshold' line (direction plus ship/abandon condition; MDE-based for proxy-only scopes, no fabricated point estimate), backed by a read-threshold requirement on the construct.md Step 4 Prediction. A behavioral-evidence block renders when a behavioral-friction signal (dead clicks, quickbacks, error rates) exists for the target surface, citing source and date. construct.md Step 9 gains a hard render check: a bundled hypothesis must carry the bundle-disclosure block with a non-empty 'This test will not isolate' line or it fails the render and must be revised before output.
- Detect triggers and untestable-differentiator routing: detect.md Step 1c gains two performance-driven triggers (a large non-search/non-self-referral source of unverified intent routes to a denominator/segmentation hypothesis or a client question; a cross-property referral with elevated quickback routes to a handoff-pathing hypothesis), plus a trigger-evaluation note to prefer routing a client question over inventing intent for an unknown population. detect-contextual.md quality-gate criterion 5 gains an untestable-differentiator routing branch: a highest-value differentiator that cannot be A/B tested (entitled-account-only, store-wide-claim-unsupportable, or otherwise structurally untestable at scope) routes to What's Not Here as a productization/positioning decision carrying its demand evidence and blocker, rather than being discarded or forced into a hypothesis; the criterion-gate prose was softened so the routing criteria (5 and 6) no longer read as a blanket discard. score.md Step 5b adds a named structurally-untestable-differentiator routing category distinct from low-traffic infeasibility.
- CTR-14 (Device/OS Defect Misattribution) added to the contrarian trigger matrix: when an OS-level or browser-family script-error defect explains a device friction gap, gate any device-targeted messaging hypothesis and route to fix-and-monitor (the fix is error remediation, not a messaging test or Core Web Vitals audit), capped at Strategic Bet tier until the error family is ruled out, because messaging tests on error-degraded sessions cannot separate message effect from error effect. The trigger-count line moved from 13 to 14, and validator section [12] now guards the contrarian-trigger count (14) and its count-line agreement, matching the pattern-count and procurement-count guards.

### Fixed
- Validator (scripts/validate-hypothesis-generator.sh) realigned to the live skill: phase-file count 3 to 4, pattern count 28 to 32, ICE calibration checks anchored to section headings (a legitimate table-column mention of 'Confidence Calibration' was tripping the exact-count-1 assertion), and both validator section [6] prohibited-content greps (em-dash and external-tool reference) extended to cover modules/contrarian-triggers.md and modules/hypothesis-interactions.md. SKILL.md operating-mode reconciliation: removed the blanket 'no YAML frontmatter' rule that contradicted the KB-mode gold artifact contract (body-purity scoped to the body, the gold frontmatter block is the only system surface), added an Operating Modes section documenting legacy and KB modes, and labeled legacy-only Preconditions framing. No behavioral change to detection, construction, or scoring.
- Cross-surface bundling reconciliation: construct.md (Experiment Scope Rule) and hypothesis-interactions.md (Same-Page Interaction Analysis Process) previously disagreed on bundling across surfaces, which permitted an uninterpretable three-surface bundle. Both files now carry the same rule verbatim with reciprocal keep-in-sync cross-references: bundle elements that serve one idea on the same page or section; across surfaces bundle only if a single failure mode can be named for a combined loss; if a combined loss would list three or more independent failures across surfaces, sequence instead of bundling.
- Module resolution hardening: Phase 1 now states that modules/<name>.md references are repository-root-relative (modules/ is a sibling of skills/, not inside the skill dir) with symlink-aware resolution for isolated or installed invocations (e.g., ~/.claude/skills/), plus a hard load-failure guard: if the pattern library, ICE calibration, or contrarian/interaction modules cannot be read, STOP and report rather than silently falling back to embedded CRO judgment. Fixes a latent failure where a symlinked invocation resolved modules/ to the empty skill dir and produced a plausible-but-unbacked roadmap. Module Dependencies notes the convention.
