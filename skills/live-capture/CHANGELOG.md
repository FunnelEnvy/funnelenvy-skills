# Changelog

## [0.2.0] - 2026-06-11

### Added
- Initial `live-capture` skill (Phase B of the observation-artifact integration). A dual-mode capture skill that navigates selected pages, passively reads the rendered DOM across desktop and mobile, and writes two factual artifacts: `live-observation.md` (page structure, blocks A-I + K plus a viewport_divergence block) and `live-copy.md` (verbatim copy). Facts and two permitted mechanical derivations only; no judgments.
- Browser-mode detection (Chrome DevTools MCP preferred, Playwright secondary, static fallback) with the configured-but-broken = STOP rule (no silent degrade), adapted from experiment-mockup.
- I/O mode resolution (legacy `.claude/context/` L0 vs KB mode), adapted from positioning-framework. KB mode writes `live-observation.md` as `bronze-note-capture` and `live-copy.md` as `bronze-research-extraction`, then enriches the silver `silver-structural-observation` artifact at `reference/cro-{scope}/live-structure.md`, with the KB frontmatter contract, prior-work supersede, and post-write `kb_type_validate.py` gate. Additive only; never a third writer to performance data.
- Section 8 page selection: `scripts/page_select.py` deterministic leverage ranking (traffic, conversion-gap-below-benchmark, bounce, device-gap weighted sum), two-lane split (conversion by leverage, content by organic sessions), always-capture homepage + positive-control, no-profile nav-crawl fallback (confidence capped at 3).
- `scripts/content_hash.py` deterministic recapture-diff hash (H1 + structural skeleton). Both scripts stdlib-only with unittest coverage in `_tests/unit/`.
- Coverage-weighted file-level confidence (not a min), tri-state existence discipline, portable fold/ordinal/region position encoding, and the capture-provenance vs KB-data_provenance distinction.
- Authoritative artifact schema inlined in `phases/write.md`; human-reference copies in `schemas/live-observation.md` and `schemas/live-copy.md`.
- Headless-WAF handling (Phase 0 + capture Step 1): enterprise WAFs (Akamai/Cloudflare/DataDome/PerimeterX/Imperva) 403 headless Chrome before content loads, so a real (non-headless) Chrome is required for WAF-protected targets. Browser-Mode Detection now documents the real-Chrome configurations (Chrome DevTools `--browserUrl`/`--wsEndpoint`; Playwright headful / `connectOverCDP`; WSLg/Xvfb on headless hosts) and states static is not a WAF remedy. A post-selection headless pre-flight probe (`navigator.webdriver` / `HeadlessChrome`) records `browser_headless` and warns before capture. A systemic-block rule stops the run when the first/all pages are WAF-blocked on a headless browser (advising a real Chrome) instead of grinding the page set into a low-confidence Access-Denied artifact; an isolated block in an otherwise-clean run still records-and-continues. `page_block_status: akamai-403` documented as the vendor-neutral WAF-403 catch-all. Surfaced by a real end-to-end run where a headless Playwright connected, then 403'd every page.

### Fixed
- QA (first live run against an enterprise WAF-protected product page, 2026-06-09) surfaced four capture-fidelity fixes, now folded in: (1) mobile uses device emulation (`emulate viewport: "390x844x3,mobile,touch"`), not `resize_page` (a window resize clamps to the attached browser minimum ~666px and silently produces a wrong mobile capture); (2) a REQUIRED scroll-load step (capture Step 1b) before extraction, so below-fold lazy content (proof, logos, testimonials, team) is in the DOM; (3) `named_client_proof_present` and `team_credibility_present` promoted from bool to tri-state (`present | absent | not_checked`) so a non-idle/partial run never emits a misleading `false`; (4) sequential-UI counts distinct component roots (not every class-substring descendant), footer detected by `[role=contentinfo]`/region (not only the `<footer>` landmark), and mega-nav `<button>` labels are captured alongside anchors.

- KB-mode resolution fix: artifact types are resolved via the two-level lookup (repo-local `artifacts/` then the kb-start base), so kb-start-inherited types like `bronze-note-capture` no longer cause a false legacy fallback. `silver-structural-observation` is the explicit KB-mode gate. Surfaced while wiring the skill into a KB whose `bronze-note-capture` is inherited from kb-start.

- Content-blocked pages no longer assert tri-state absence (surfaced by the first full KB-mode chain run). A page hard-blocked by a WAF (`page_block_status: akamai-403` / `challenge`, zero content rendered) had no detection pass run against rendered content, so it now writes every pass-dependent tri-state field as `not_checked` (never `absent`) and pass-dependent counts as `null` (never an observed-looking `0`). `partial` pages that did render keep their real observations. Rule added to `agent-header.md`, `phases/capture.md`, `phases/write.md`, and `phases/static-capture.md`. The consumer (hypothesis-generator) needs no change: its `not_checked`-neither-fires-nor-suppresses rule already handles the corrected output.
- Schema completeness: declared two emitted-but-undeclared fields in the authoritative schema (`phases/write.md`) and mirrored them in `schemas/live-observation.md`: site-level `sitewide_form_field_count` (perceived-length sibling of `sitewide_form_required_field_count`) and per-page `name` (human-readable page label alongside `path`).
- `objection_faq_present` is now emitted explicitly as `not_checked` until a detection pass exists, rather than omitted. Schema-complete and honest about the absent pass; the field is retained because hypothesis-generator Step 1e keys TC-02 on it.
